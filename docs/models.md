# 支持的模型协议

本库只实现下列显式协议。三个文件缺一不可；文件扩展名为 ONNX 并不代表兼容。模型权重和导出器需由调用者自行合法取得；本仓库没有已经验证的公开真人音色下载链接，也没有现成 `.pth` 导出工具。

## Content encoder

| 方向 | 名称 | 类型 | 形状 |
|---|---|---|---|
| 输入 | `source` | float32 | `[1, 1, N]`，16 kHz 单声道 |
| 输出 | `embed` | float32 | `[1, T, D]`，D 为 256 或 768 |

实现假设内容特征帧率约为 50 Hz，通过复制每帧两次得到合成器约 100 Hz 的输入。`feature_dimension` 必须与实际输出一致。使用不同帧率或插值策略的模型需要适配。

## F0 encoder

| 方向 | 名称 | 类型 | 形状 |
|---|---|---|---|
| 输入 | `waveform` | float32 | `[1, N]`，16 kHz |
| 输入 | `threshold` | float32 | `[1]` |
| 输出 | `f0` | float32 | `[1, P]`，单位 Hz；0 表示无声带振动 |
| 输出 | `uv` | float32 | `[1, P]` |

这是特定的 RMVPE 风格导出协议；其他 F0 导出格式需要适配。当前以 `f0=0` 表示无声，`uv` 要求存在但不参与处理。F0 插值到内容帧数，升降调后转换为 coarse pitch。

## Voice synthesizer

| 方向 | 名称 | 类型 | 形状 |
|---|---|---|---|
| 输入 | `phone` | float32 | `[1, F, D]` |
| 输入 | `phone_lengths` | int64 | `[1]`，数值 F |
| 输入 | `pitch` | int64 | `[1, F]`，范围 1–255 |
| 输入 | `pitchf` | float32 | `[1, F]`，Hz |
| 输入 | `ds` | int64 | `[1]`，speaker id |
| 输入 | `rnd` | float32 | `[1, 192, F]` |
| 输出 | `audio` | float32 | `[1, 1, M]` |

F 为 content 输出帧数的两倍。声音输出采样率由 `dvc_model_config.sample_rate` 指定，不从文件名猜测。`speaker_count` 是模型元数据，speaker id 必须小于它。

加载时校验端口数量、名称、元素类型和 rank；具体动态尺寸在推理时校验。需要输入维度动态、支持配置的 clip/window 长度。图的最终音频会重采样到调用方采样率，裁剪或补零到调用方输入长度；导出器时间轴错配可能导致尾部补零，必须用真实模型进一步检查。

## 集成约定

- 三个 ONNX 模型路径均由调用方显式指定。
- 模型会话属于各自实例，不跨实例或设备共享。
- 当前不包含 FAISS 检索、protect/index rate 或响度匹配。
- 与其他推理实现比较时，应对齐重采样、F0 边界处理、交叉淡化和随机参数。

## 真实模型验收要记录

模型出处/许可、SHA-256、导出器提交、采样率、特征维度、端口签名、speaker 数量、输入声音许可、参考输出及硬件。至少测静音、男女声、升降调、长时间分块和切换音色。只加载可信模型；本库不提供不可信 ONNX 的隔离执行环境。
